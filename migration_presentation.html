ภาพรวมการย้ายระบบ (Executive Overview)

การเปรียบเทียบเชิงยุทธศาสตร์ระหว่างระบบเดิม (Single Docker Host) กับระบบใหม่ (Talos K8s Cluster) ครอบคลุม 8 มิติสำคัญ

Legacy Architecture

Single-Server Docker Host

🖥️
  • ❌ Single Point of Failure (SPOF) - เครื่องล่ม ระบบดับทั้งบริษัท
  • ❌ Manual Scaling - ขยายเครื่องต้องปิดปรับปรุงระบบ (Downtime)
  • ❌ Local Host Storage - ข้อมูลผูกติดดิสก์เครื่องเดียว ย้ายไม่ได้
  • ❌ SSH Deployment Script - เสี่ยงต่อการสคริปต์หลุด พลาดแล้วย้อนยาก
Modern Architecture

7-Node Talos Kubernetes Cluster

☸️
  • ✅ High Availability (HA) - 3 Control Planes + 4 Worker Nodes
  • ✅ Horizontal Auto-scaling (HPA) - ปรับ 2 ➔ 10 Replicas อัตโนมัติ
  • ✅ Distributed Rook-Ceph Storage - Shared Volume ปลอดภัยสูง
  • ✅ Zero-Downtime Deployment & 3-Second Instant Rollback
Dimension 1

ความทนทานและการซ่อมแซมตัวเอง (High Availability & Self-Healing)

🔴 Docker Single-Server

พึ่งพาฮาร์ดแวร์และ OS ของเครื่องเดียว หาก OS แฮงก์, CPU Overheat, หรือเน็ตหลุด คอนเทนเนอร์ทั้งหมดจะหยุดทำงานทันที

Downtime = เวลาที่ใช้ตามช่าง + บูตเครื่องใหม่ (15-60 นาที)

🟢 Kubernetes Cluster

หาก Worker Node เครื่องใดเครื่องหนึ่งตาย Pods จะถูกย้ายไปรันต่อที่ Worker เครื่องอื่นทันที (Self-Healing) โดยผู้ใช้ไม่รู้สึกถึงความสะดุด

Self-Healing Event = Kubelet ตรวจพบ Node ตาย ➔ Reschedule ไปเครื่องอื่นอัตโนมัติ (< 30 วินาที)
Dimension 2

การขยายระบบและการจัดการทรัพยากร (Scalability & Resource Management)

Single Server Docker

- ขนาดจำกัดตาม Spec ฮาร์ดแวร์เครื่องเดียว
- หากผู้ใช้พุ่งสูง (Peak Traffic) เครื่องจะ RAM เต็มและ Crash
- ไม่มีการจำกัด Resource Limits ที่ชัดเจน อาจทำให้ตู้เดียวดึง RAM เครื่องจนค้าง

Kubernetes HPA (HorizontalPodAutoscaler)

- กำหนด Min: 2 Replicas / Max: 10 Replicas อัตโนมัติ
- เมื่อ CPU > 75% หรือ RAM > 80% K8s จะสั่งปั๊ม Pods เพิ่มทันที
- กระจายภาระงานไปยัง 4 Worker Nodes อย่างสมดุล

Dimension 3

ระบบจัดเก็บข้อมูล (Storage & Data Persistence)

🔴 Local Host Path (-v /home/jenkins/tms/...)

- ไฟล์ ApiLogs, Master, Permission ผูกติดกับดิสก์ของเครื่อง `10.1.1.5`
- หากดิสก์เครื่องนั้นเสีย ข้อมูลสูญหายทั้งหมด (Loss of Data)
- ไม่รองรับการรันหลายคอนเทนเนอร์พร้อมกัน (Lock Conflict)

🟢 Rook-Ceph Distributed Storage (PVC)

- ข้อมูลถูกทำ Replicas กระจายดิสก์บน 4 Worker Nodes
- ใช้ `ReadWriteMany` (CephFS) ให้ทุก Pods อ่าน/เขียนไฟล์ร่วมกันได้พร้อมกัน
- หาก Node ใด Node หนึ่งดิสก์พัง ข้อมูลยังมีสำรองบน Node อื่นครบถ้วน

Dimension 4

เครือข่ายและการจัดเส้นทาง Traffic (Networking & Ingress)

สถาปัตยกรรมที่ลงตัว: Nginx Proxy Manager + NGINX Gateway Fabric

ใช้ **Nginx Proxy Manager (`10.1.1.150`)** ทำหน้าที่ดูแล SSL Certificate & Domain ภายนอก แล้วส่งต่อ HTTP Traffic เข้าหา **NGINX Gateway Fabric** ใน K8s เพื่อกระจายลง Pods

วิธีเดิม: Direct Port (-p 7020:8080)

พอร์ตชนกันง่าย แยกรートตาม URI ลำบาก และต้องแก้ไข Nginx Proxy Manager ชี้เจาะจง IP เดียว

วิธีใหม่: Service + HTTPRoute

ทำ Load Balancing อัตโนมัติระหว่าง Pods 2-10 ตัว และรองรับ WebSocket, Path Routing อย่างสมบูรณ์

Dimension 5

การ Deploy และการถอยกลับ (CI/CD Deployment & Rollback)

🔴 Traditional SSH Docker Run

  • • สั่ง `docker stop` และ `docker rm` ตู้เก่าก่อนรันตู้ใหม่ ➔ มี Downtime ชัดเจน
  • • Rollback ช้า: ต้องแก้เลข Tag ใน Jenkinsfile แล้วกดรัน Pipeline ใหม่ (1-3 นาที)

🟢 Kubernetes Rolling Update & Rollback

  • • Rolling Update: สั่งสร้าง Pod ใหม่ให้ Ready ก่อน แล้วค่อยปลด Pod เก่าออก ➔ Zero Downtime
  • • Instant Rollback (< 3 วินาที): เพียงรันคำสั่ง kubectl rollout undo deployment/tms-backend-prod สลับกลับทันที
Dimension 6

ความปลอดภัยและการจัดการความลับ (Security & Secret Management)

🔴 Docker Host เดิม

- ไฟล์ Key/Cert (`private_key.pem`) ฝังไว้ในโฟลเดอร์เครื่อง หรือ Build เข้า Image
- ใครมีสิทธิ์เข้าเครื่อง SSH `10.1.1.5` สามารถแอบดู Environment Variables และไฟล์ทั้งหมดได้
- ไม่มีระบบสิทธิ์ระดับย่อย (RBAC)

🟢 Kubernetes Security Model

- จัดเก็บความลับผ่าน **Kubernetes Secrets** ถอดรหัส memory-only ให้เฉพาะ Pod ที่ได้รับสิทธิ์
- ดึง Image ผ่าน `imagePullSecrets` (`nexus-regcred`) อย่างปลอดภัย
- ควบคุมสิทธิ์ด้วย **RBAC (Role-Based Access Control)** และ Network Policies

Dimension 7

การเฝ้าระวังและติดตามสถานะระบบ (Monitoring & Observability)

🔴 Docker Manual Inspection

- ต้อง SSH เข้าเครื่องไปรัน `docker ps` หรือ `docker logs` ดูทีละตู้
- ไม่มีระบบสถิติการใช้งาน CPU/RAM ย้อนหลัง
- ไม่มีระบบแจ้งเตือนอัตโนมัติเมื่อ Container ค้างหรือ Crash

🟢 Kubernetes Observability Stack

- ตรวจสอบผ่าน **Headlamp Dashboard**, **Prometheus**, และ **Grafana** (มีรันอยู่ใน Cluster แล้ว)
- **Metrics Server** ติดตามการใช้งาน CPU/RAM Real-time
- Liveness & Readiness Probes ตรวจสุขภาพ Pods อัตโนมัติทุก 10-15 วินาที

Summary Matrix

ตารางเปรียบเทียบสรุปทุกมิติ (Comparison Matrix)

มิติ (Dimension) Single-Server Docker Kubernetes Cluster (Talos)
1. High Availability ❌ มีจุดล้มเหลวเดี่ยว (SPOF) ✅ HA 7 Nodes (3 CP + 4 Workers)
2. Auto-scaling ❌ สเกลมือ (Manual Resize) ✅ HPA อัตโนมัติ (2 - 10 Replicas)
3. Data Persistence ❌ Local Disk เครื่องเดียว ✅ Rook-Ceph Distributed Storage
4. Deployment Downtime ❌ มี Downtime ตอน Stop/Run ✅ Zero Downtime (Rolling Update)
5. Rollback Speed ❌ 1-3 นาที (Re-run Jenkins) ✅ < 3 วินาที (`kubectl rollout undo`)
6. Health Probes ❌ Docker restart always พื้นฐาน ✅ Liveness / Readiness Probes ชัดเจน
